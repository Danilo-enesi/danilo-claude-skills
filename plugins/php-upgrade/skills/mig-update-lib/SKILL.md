# mig-update-lib

**Rule:** libraries are swapped whole by `update-lib.sh`, never edited. The callers are project code: their API usage must be checked before applying.

## 1. Version (one approval from the user)
- Latest stable of the **same major line** the SPEC targets, published at least ~2 weeks ago; check the changelog/composer `php` constraint for the target PHP. Read GitHub through the API (`curl -s https://api.github.com/repos/<repo>/tags` or `/contents/<dir>?ref=<tag>`): the guard blocks downloads outside `update-lib.sh`.
- Known traps: **TCPDF 7.x** is a wrapper of tc-lib-pdf (stay on 6.x); TCPDF ≥ 6.11.3 emits a runtime `E_USER_DEPRECATED` (bad where PDFs force `display_errors`). FPDI 2.x extends TCPDF: update them together.
- Show version + zip URL (`https://github.com/<repo>/archive/refs/tags/<tag>.zip`) and the files to keep in the same message.

## 2. Files to keep
Compare the current folder with the original release: project-added files go in «da-tenere» (globs allowed, e.g. `fonts/opensans*` generated by `addTTFfont`). Exclude `examples,tools,test,docs`. Config files that only hold default paths are not kept (say so).

## 3. Lock and swap
1. `libs.lock` line with sha256 `-`; `bash $PU/update-lib.sh <name> --download` prints the SHA-256: show it with the next action (it only pins that this exact zip is what goes to PROD) and write it after the user's ok.
2. `update-lib.sh <name>` (dry-run) → `--apply`. Files the new version removed are fine (lint skips them).
3. Our files on top of the library go in `_migration/files/lib-<name>/` (e.g. the PHPMailer 6 shim `class.phpmailer.php`: requires `src/`, `class_alias` for `PHPMailer`, `SMTP`, `phpmailerException`; callers untouched).

## 4. Caller API (before committing)
grep every method of the library used by the project and check it still exists in the new version. Seen: tcpdf 6 `addTTFfont()` → `\TCPDF_FONTS::addTTFfont(...)` (static, same args). PHPMailer: method names are case-insensitive, `new PHPMailer` without `true` throws nothing. Propose caller changes together.

## 5. Verify
- Library check (L*) PASS. PDFs: `run-tests.sh --smoke`, then open 2-3 PDFs vs PROD. `TCPDF ERROR: Some data has already been output` = a warning/deprecation printed before the PDF; where the code forces `error_reporting(-1)`+`display_errors` exclude `E_DEPRECATED|E_USER_DEPRECATED` there (it happens in PROD too) instead of chasing deprecations one by one.
- Mail: if callers use `isSMTP()` with real hosts, **never send from the site**. Test with a scratchpad script that requires the shim like the site and sends via SMTP to Mailpit `127.0.0.1:1025` (no auth, no auto-TLS; UTF-8, HTML, attachment); check `curl -s "http://127.0.0.1:8025/api/v1/messages?limit=1"`. Write the script with Write, not a heredoc. Real sending is tested in PROD (P6).
- If the whole front is down for another reason, commit with the library checks PASS and say in the commit message that PDF/mail verification moves to L7.
- Commit: `PHP <PHP_TO>: <lib> <ver>`.

## If it fails
`update-lib.sh` restores the old folder if the new one does not compile. Wrong output: `bash $PU/rollback.sh`, stop and report.
